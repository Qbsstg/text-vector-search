## API与算法

严格使用API v1.0：POST `/api/search`，输入`{text,topK,channel?}`，200 `{hits:[{documentId,channel,score,snippet}]}`，不新增字段或data壳。text非null字符串、允许空/纯空白；原始和规范化各≤20000 code points。topK必须JSON整数1—100，不接受小数/字符串/null/溢出。渠道省略或null为全部，显式Unicode空白400；非空仅trim、区分大小写。延续JSON根对象、实际字节限额、同源Origin及统一错误结构。

统一调用现有TextEmbedder、VectorCodec、CosineSimilarity、TopKSelector，版本仍`char12-sha256-r32-nfkc-root-ws-v1`。不得复制或改写算法，零向量余弦0，负/零分保留，无阈值，同分ASCII ID升序，K>N返回全部。snippet是原文前200 code points，不能按UTF-16单元硬截断；前端纯文本。

## 候选快照、资源与关闭

1. 单次候选SQL/短读取阶段包含：关联任务SUCCEEDED、vector_bytes存在且1024字节、文档未失效、文档和任务版本均等于统一算法版本、可选渠道精确过滤。先过滤再评分/Top-K，不默认截断候选。
2. 读取结果是本次快照；失效已提交后新开始的搜索排除该文档，重叠在途搜索允许返回快照中的旧候选。计数阶段不能重新过滤而造成已返回命中漏计，不整体覆盖失效/时间/向量。
3. CPU向量化/解码/评分与Top-K均在事务和数据库连接之外。查询并发许可使用冻结search-permits=1，不排无界等待，许可忙429 SEARCH_BUSY；许可覆盖查询计算、候选读取、评分及计数物理提交，所有退出路径释放。
4. 最大5000文档、256维、K≤100、Hikari4连接保持。候选不加载全部原文CLOB；可在候选SQL读取有界原文前缀（最多足够容纳200个code points）或在Top-K后读取不可变原文片段。内存只保存有界候选元信息/向量与Top-K，不新增缓存或服务依赖。若检测库数据超过契约上限，应明确失败，不静默截断并返回不完整Top-K。
5. 恢复/降级/停止门禁沿用B3。候选短读取与计数短事务使用共享TaskWriteBarrier许可，包含真实提交/回滚；CPU不持许可。停止期间尚在CPU的搜索不能在数据源销毁后访问SQL；进入计数前重新核对就绪，关闭许可后503、不计数。

## 计数事务与未知结果

- 全部候选评分并确定最终Top-K后，复制最终ID按ASCII固定顺序更新：`hit_count=hit_count+1`。同一独立短物理事务完成所有K项，每行必须受影响1行，否则整体回滚。仅更新hit_count，不读改写、不更新全部候选、不重排返回结果。空命中返回空列表，不制造写入。
- 计数成功提交才返回200；明确回滚返回诚实数据库错误。允许对已证明物理回滚的暂时错误有限重试，但非必需；若实现，必须限制次数并独立验证。不得把回调结束当成实际commit，禁止未知外层事务包裹导致误报成功。
- 任何无法确认的commit结果返回503 RESULT_UNKNOWN并进入可观测DEGRADED，不能再次自增，也不能通过当前累计hit_count推断该请求是否提交。无请求幂等标识或DDL旁路。
- commit成功后客户端断开仍已计数；服务端不重放，前端提交/搜索/网络失败/RESULT_UNKNOWN均不自动重试，提示可能已计数。诊断GET不计数。
- BIGINT溢出、行数异常、第二项写失败等必须回滚全部增量，不回假成功、不覆盖原状态。异常对外不泄露SQL/用户文本/路径。
