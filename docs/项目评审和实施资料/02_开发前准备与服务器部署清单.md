# 开发前准备与服务器部署清单

> 日期：2026-10-22；版本V1.1。  
> 本文是待执行清单与运维设计，不代表环境已检查、服务器已购买或部署已完成。所有复选框默认未完成。

## 1. 先确定七件事

| 事项 | 推荐决定 | 需要你准备的内容 |
|---|---|---|
| 开发方式 | 本地开发，CI或本地构建，服务器运行 | 可用Java17/Maven环境与Codex |
| 服务器 | 2 vCPU、4GiB内存、40GiB SSD | 云主机、公网或受控网络入口、SSH密钥 |
| 数据库 | H2嵌入式文件，不装MySQL | 持久目录与读写权限 |
| GitHub | 单仓库，默认先私有 | 仓库、认证、评审访问方式 |
| 页面 | 原生HTML/CSS/JS同源托管 | 接受最小三功能区，不要求完整聊天界面 |
| Agent协作 | 主控+少量独立任务 | 分支/worktree、契约、文件所有权 |
| 演示访问 | HTTPS+入口认证，或SSH/VPN受控访问 | 可用域名/证书方案或受控访问方案 |

这些是本项目建议，不是服务器供应商官方最低配置。原题明确H2文件持久化，服务器部署是原题加分项、也是用户本轮明确目标。[P1]

## 2. 本地开发环境准备

### 2.1 必须先检查

- [ ] `java -version`与`./mvnw -version`使用同一目标JDK，编译release=17。
- [ ] Maven Wrapper可以下载依赖、运行测试和生成可执行JAR。
- [ ] Git可以完成真实commit及push，提交身份正确。
- [ ] Codex能够打开项目、读写工作目录并执行测试；先用最小任务验证，不把首次登录问题留到开发中途。
- [ ] IDE能运行一个空Spring应用，使用文件模式H2。
- [ ] 本地与服务器使用相同算法版本、JDK发行版/版本；跨环境黄金向量测试可执行。
- [ ] 终端UTF-8、脚本换行与Linux执行权限正常。

已有研究曾记录本地Java和Maven使用的JVM不一致；这是历史检查信息，本次没有直接检查你的机器，必须重新确认。[P2，第3节]

### 2.2 前端不需要先准备复杂工具链

默认原生HTML/CSS/JS放入`src/main/resources/static/`，无需Node服务、Vue CLI、前后端分开部署或跨域配置。Spring Boot支持静态资源托管。[S1]

如果你已熟悉Vue且确有复用资产，可以使用本地构建后的静态资源，但不得让Node运行环境成为服务器必需依赖。不要为了一个演示页同时引入React/Vue、SSR、复杂状态管理和多仓库。

### 2.3 数据与样例

- [ ] 准备10—20条合成FAQ，至少两种渠道。
- [ ] 准备同文、局部改写、无关、单字、空文本、emoji和否定关系样例。
- [ ] 文档ID带唯一演示批次前缀，防止重复运行因409产生混淆。
- [ ] 不使用公司的真实客户数据或私人聊天内容。
- [ ] 样例脚本不能静默吞掉409、429或失败任务。
- [ ] 重复演示前明确是复用历史记录还是使用全新独立数据目录；不要在正式演示入口提供“一键清库”。

## 3. 服务器怎么选

### 3.1 建议配置

| 档位 | 配置 | 判断 |
|---|---|---|
| 最省 | 2vCPU / 2GiB / 20—40GiB SSD | 可尝试低并发演示，不建议同机编译与压测；需要实测内存 |
| 推荐 | **2vCPU / 4GiB / 40GiB SSD** | 更适合应用、H2、代理和基础诊断同时运行 |
| 开发运行合用 | 4vCPU / 8GiB / 40—60GiB SSD | 适合额外构建/测试进程，但仍需隔离数据和端口 |

不需要GPU、云MySQL、Redis、消息队列或负载均衡实例。该方案不运行真实模型，主要做本地确定性算法。

带宽先按3—5Mbps文本演示预算评估，不宣称支持固定人数或QPS；长文本返回、多人同时演示、远距离网络会改变体验。注意云厂商的共享CPU、突发积分、出站流量和续费条件，本报告没有查价、没有推荐具体购买套餐。

### 3.2 主机准备

- [ ] 选择仍受支持、自己熟悉的Linux LTS，例如Ubuntu24.04 LTS；不要选择多年未维护镜像。[S2]
- [ ] 配置SSH密钥登录和非root服务账号。
- [ ] 设置安全组和主机防火墙；SSH尽量限制来源，不把管理端口全部开放。
- [ ] 在自己和评审常用网络测试可达性；地域选择以访问条件为准，不假定某个地域一定更快。
- [ ] 安装Java17运行环境、systemd所需配置及Nginx。
- [ ] 确认磁盘空间、时间同步、目录权限；日志设置容量/保留周期。
- [ ] 确认可用域名、DNS和HTTPS证书路径；云厂商的接入条件提前核对，不把域名配置问题留到最后半小时。
- [ ] 确认预算、使用时长和结束后的资源清理方式，避免长期闲置收费。

## 4. 为什么不直接在唯一演示服务器开发

推荐的责任划分：

```text
本地：编辑、Agent、单测、并发/故障测试
GitHub：源码、审查、CI、构建证据
服务器：固定版本运行、授权访问、部署验收
```

在演示服务器直接开发会让编译和测试竞争CPU，可能误用正式H2路径、多进程争锁、把断点和故障注入带入演示，且容易留下密钥与未提交补丁。

远程开发仅作本地确实不可用时的替代。至少做到不同用户、端口、数据目录；正式演示进程不允许被Agent直接任意重启。2核4GiB服务器不宜同时承担多个Maven构建和演示。

**部署应尽早试跑，而不是等开发全部结束。** 第一个空应用与静态页面出来后，就验证一次SSH、JAR、文件写入、访问入口；最后只是在已经可用的路径上替换经过测试的版本。

## 5. H2准备：一个依赖、一套文件，不是两个数据库

### 5.1 运行方式

H2嵌入应用JVM，通过JDBC访问本地文件；不需要单独H2进程，不开放H2端口，不安装MySQL。[P1；S3]

推荐固定路径：

```text
数据库连接：jdbc:h2:file:/var/lib/vector-search/db/knowledge;WRITE_DELAY=0
实际主文件示例：/var/lib/vector-search/db/knowledge.mv.db
```

URL中写数据库基名，不手动把`.mv.db`附加为数据库名。路径、文件名和引擎行为以锁定H2版本验证。WRITE_DELAY=0减少异步刷写窗口，但不等于对断电/硬件故障绝对安全，应测其写入成本。[S3、S4]

### 5.2 必须保证

- [ ] 数据库位于release/target/Git仓库之外的持久目录。
- [ ] 服务账号可读写，其他无关账号不能读取业务文件。
- [ ] 本地、CI、测试、演示分别使用独立数据库路径。
- [ ] 启动自动执行幂等DDL，第二次启动不清空记录。
- [ ] 禁止`create-drop`、开机重置数据、自动换成`jdbc:h2:mem:`。
- [ ] 禁止两个正式应用实例同时使用该嵌入式文件；不随意启用AUTO_SERVER或关闭文件锁来“解决”冲突。
- [ ] H2 Console不对公网开放，正式配置默认关闭。
- [ ] 原文、向量、任务、失效和命中数全部使用同一H2事实来源。

## 6. 部署目录与进程管理

### 6.1 目录

```text
/opt/vector-search/releases/<git-sha>/app.jar   # 不可变发布包
/opt/vector-search/current                    # 当前版本链接
/var/lib/vector-search/db/                    # H2持久文件
/etc/vector-search/app.env                    # 外部配置/凭据
/var/backups/vector-search/                   # 有保留策略的备份
```

所有运行数据库与凭据都不进入Git。版本目录由部署账号维护，应用账号仅拥有运行所需权限。

### 6.2 配置责任

建议应用读取`APP_DATA_DIR`等配置变量；具体名字在仓库统一定义，不假设以下自定义变量Spring会自动识别。Spring标准变量如`SPRING_PROFILES_ACTIVE`和自定义业务参数应区分。

服务器示例配置约定：

| 配置 | 起始值/策略 | 注意 |
|---|---|---|
| 监听 | 127.0.0.1:8080 | 仅Nginx或SSH隧道访问 |
| JVM堆 | Xms256m、Xmx1024m | 4GiB机器起点，非RSS上限 |
| Worker | 1 | 先给检索和系统留余量 |
| 搜索同时执行许可 | 1 | 超限快速返回繁忙，不无限等待 |
| 内存任务队列 | 64 | 数据库待处理量另设上限 |
| 待处理任务 | 1000 | QUEUED+RUNNING上限 |
| 文档总量 | 5000 | 超限明确拒绝，不偷偷截断检索 |
| 文本 | 原始与规范化后均≤20000 code points | JSON体另有限制 |
| topK/分页 | 最大100 | 非法值返回400 |
| 请求体 | 256KiB | 代理与应用层都应限制 |

上述均未压测，不应宣传为生产容量。

### 6.3 systemd配置审查点

不是让SSH终端长期运行`java -jar`或仅依靠nohup。systemd负责进程生命周期与失败重启；数据库/任务是否健康仍由应用和验收负责。[S5]

- [ ] `User`为专用非root账号。
- [ ] `WorkingDirectory`稳定，但数据库仍使用绝对路径。
- [ ] `ExecStart`指向确认存在的Java17和当前JAR。
- [ ] `EnvironmentFile`权限受限，不能通过代码仓库分发真实值。
- [ ] `Restart=on-failure`及退避/启动频率限制合理，防止错误配置无限重启刷日志。
- [ ] 关闭等待时间覆盖应用有界优雅关闭；先停派发，再等任务，再关H2。
- [ ] 日志可通过journalctl定位，敏感文本与凭据不写入日志。
- [ ] 重启机器后服务能自动恢复；单纯关闭SSH也不会使应用退出。

正式unit由部署Agent按真实机器路径生成并验证，不把本文当已可执行脚本。

## 7. 公网入口安全

Nginx代理全部页面和API到同一后端；HTTPS、入口认证及必要限流由代理承担。[S6、S7、S8]

- [ ] 443用于HTTPS；80仅按证书/重定向需求开放；22限管理来源。
- [ ] 不直接开放8080，不暴露8082等H2 Console端口，不安装或开放3306。
- [ ] 认证覆盖`/`和`/api/`，不能只保护首页。
- [ ] Basic Auth必须配合HTTPS；用户名密码单独给评审，不放README、URL、JS或Git历史。
- [ ] 同源请求不开放任意CORS；写接口只接受约定JSON和方法，浏览器写入需Origin校验或CSRF机制。
- [ ] 前端将原文和错误信息作为文本展示，不用innerHTML直接拼接。
- [ ] 非必要的Actuator、env、heapdump、SQL Console不对外开放。
- [ ] 请求体、并发执行数和速率限制配合使用；速率限制不代替应用的CPU并发限制。
- [ ] 只放合成数据，失败信息不泄露文件路径、SQL凭据和完整堆栈。

证书/域名暂未就绪时可先通过SSH隧道或VPN进行授权验收。不要将“为了演示方便”解释为允许裸露管理API。公网保护是演示环境措施，不声称已经建设企业权限体系。

## 8. 发布、备份与回滚

### 8.1 首次发布

1. 本地/CI在锁定JDK下执行`./mvnw -B clean verify`，核对实际执行的测试。
2. 记录源码SHA、JAR文件名与SHA-256；不要从未知工作区随手复制一个旧JAR。
3. 上传新的版本目录，不覆盖数据库目录。
4. 配置服务账号、外部配置、数据目录、入口代理。
5. 启动后验证本机健康、授权入口、提交任务、任务完成、检索、失效、计数。
6. 正常重启服务，确认同一数据库和统计保留。
7. 记录部署版本、时间和真实结果，不把未运行的用例标为通过。

### 8.2 更新发布

H2单实例采用短暂停机更新，不做两个版本同时挂同库的蓝绿发布。

1. 新包上传到独立release目录，先做静态校验。
2. 停止接收和后台派发，正常停止服务并确认进程退出。
3. 数据库关闭后做备份，记录版本和校验值。
4. 更新current指向，再启动唯一应用进程。
5. 执行同一套冒烟流程；失败时按回滚兼容性处理。

### 8.3 备份与恢复

H2支持SQL在线备份等方式；普通文件复制应在数据库关闭后进行，不直接复制正在变化的活动文件。[S9]

- [ ] 初版优先“正常停服务→确认退出→复制数据库→启动”。
- [ ] 备份文件不得进公网目录和Git；限制权限并设置保留周期。
- [ ] 至少一次把备份恢复到**另一个临时路径/端口**，确认文档与元数据可读；不能只验证zip存在。
- [ ] 回滚前确认旧程序是否兼容新schema；不兼容则不能只改current链接。
- [ ] 恢复备份会丢弃备份后的写入，必须明确影响，不能暗中覆盖数据。
- [ ] H2版本升级不混在临近截止的普通功能发布中。

## 9. GitHub准备与仓库纪律

### 9.1 仓库准备

- [ ] 创建单仓库；优先私有，明确评审访问方式。
- [ ] README写清项目定位、模拟算法边界、启动/测试/部署命令、演示与限制。
- [ ] 添加Maven Wrapper、AGENTS.md、需求/接口契约、测试计划。
- [ ] 原题PDF是否允许公开单独确认；不能因自己有文件就默认能上传到公开仓库。
- [ ] AI关键对话保留需求澄清、方案反驳、失败测试修复，脱敏后入库。
- [ ] 配置最小CI：JDK17、构建、单测、集成测试、报告；暂不自动部署。[S10]
- [ ] 测试配置确认`*IT`是否由Failsafe执行，防止CI绿但没有运行恢复/并发用例。[S13]
- [ ] 根据仓库计划能力配置保护规则；无保护功能时也执行人工合并门禁。

### 9.2 .gitignore建议范围

```gitignore
/target/
/data/
/logs/
*.mv.db
*.trace.db
*.lock.db
.env
.env.*
!.env.example
*.pem
*.key
.idea/
.DS_Store
```

不要忽略应交付的`.mvn/`和Wrapper脚本；`.env.example`只能包含占位值。所有模式应先检查仓库路径，避免把测试夹具误排除。

### 9.3 安全与记录

GitHub Actions权限最小化，可信Action固定完整提交SHA，生产发布不自动执行来自不可信PR的代码。生产主机不作为任意PR可使用的自托管Runner。[S11]

密钥已泄漏时先撤销/轮换，再处理历史；仅删除工作区文件不足以清除泄漏。[S12]

真实分阶段提交可以围绕“启动骨架、算法测试、持久任务、检索、竞态修复、前端、部署、文档”。不伪造时间，不为了好看把失败过程完全删掉。最终tag关联真实通过的版本。

## 10. 交付前检查

- [ ] 全新目录拉取源码可构建，不依赖开发机绝对路径。
- [ ] 服务器运行版本对应已知Git SHA，JAR校验值一致。
- [ ] 页面能完成提交→任务→检索→失效→再次检索。
- [ ] 任务为真实状态；没有假百分比或硬编码相似度。
- [ ] 关闭SSH、重启服务后应用仍正常，文档/任务/计数保留。
- [ ] H2与管理端口未对外开放；未认证请求无法访问受保护API。
- [ ] 关键并发/恢复测试有真实报告；未执行项明确列出。
- [ ] 没有提交日志、数据库、凭据、target或未经授权的招聘资料。
- [ ] README、PRD、接口实现对空文本、渠道缺省、同分和统计语义一致。
- [ ] 演示账号、访问地址与有效使用条件单独告知评审。
- [ ] 预留至少30分钟处理网络、证书、权限或错误包等交付问题。

## 11. 最先做的顺序

先验证Java/Maven和Codex，再准备GitHub及2核4GiB主机；冻结接口后让后端开工，部署角色立刻试跑骨架，前端按固定契约制作单页；随后将重心转到一致性测试与真实服务器复演。不要先花时间购买数据库或搭建复杂前端框架。
