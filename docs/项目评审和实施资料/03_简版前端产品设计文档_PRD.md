# 文本向量化与检索演示台——简版前端产品设计文档

> 版本：V1.0；日期：2026-10-22。  
> 属性：待实施PRD，不是已完成页面；没有生成项目代码或声称完成浏览器验收。  
> 范围来源：用户本轮新增的简单前端需求。原笔试没有要求前端，但本页用于展示原题六项业务能力。

## 1. 产品目标

让评审者不必先阅读curl命令，就能理解并操作“文档提交—后台向量化—检索—来源追溯—文档失效”的闭环。界面必须忠实于真实后端，不能用模拟进度、随机分数或预设答案美化功能。

核心定位：**文本检索演示台，而非AI聊天产品。** 固定提示“本项目使用确定性的模拟向量算法，体现字面特征相似，不保证语义理解”。

### 1.1 用户与成功标准

| 用户 | 任务 | 成功表现 |
|---|---|---|
| 面试官/评审者 | 快速验证是否符合题目 | 能提交、追踪、搜索和失效，不需要隐藏步骤 |
| 候选开发者 | 演示和排查 | 看得见taskId、状态、渠道、时间、计数与错误 |
| 知识维护角色（演示） | 管理少量知识 | 列表与详情清晰，失效有确认和反馈 |

### 1.2 不做

不做聊天气泡、LLM回答、文档文件上传、Markdown富文本渲染、拖拽解析、账户管理、权限分层、仪表盘、图表统计、批量编辑、失败重试按钮、恢复有效、向量可视化和复杂动画。样例只能填入表单，不能假装后端已存在数据。

## 2. 技术与信息架构

### 2.1 技术建议

原生HTML/CSS/JavaScript，文件位于`src/main/resources/static/`，由同一个Spring Boot进程托管，与`/api/`同源。无Node运行服务，无跨域依赖，无外部CDN必需资源。Spring Boot官方支持这一静态资源组织方式。[S1]

若后续更换为Vue等框架，仍保持API契约和单一部署方式；此次不因视觉层换技术栈重做后端。

### 2.2 一个页面，三个Tab，一个详情抽屉

```text
页头：文本检索演示台 | 模拟向量说明 | 帮助
导航：检索体验（默认） | 文档管理 | 任务追踪
内容：当前Tab对应表单、结果和反馈
侧栏/抽屉：文档详情、原文和关联任务
页脚：接口/README提示；版本仅在有真实来源时显示
```

不使用“全库统计”卡片，避免增加汇总接口或把当前页统计冒充全库统计。健康/版本信息只有后端已实现相应接口或构建注入时才展示，不硬编码“服务正常”。

## 3. 核心用户流程

### 3.1 入库到检索

进入文档管理 → 输入ID、原文、可选渠道 → 提交 → 显示202接收结果与taskId → 开始有限轮询 → 状态成功 → 点击“前往检索”，手动查询 → 查看真实Top-K及来源。

提交按钮完成HTTP响应后恢复可用，不等待向量化结束。任务失败与提交失败分开呈现。

### 3.2 检索到失效

进入检索体验 → 输入text、topK、可选channel → 点击检索 → 展示排序结果 → 点击文档详情 → 确认失效 → 显示后端返回结果 → 手动再次搜索验证排除。

失效后旧结果标记“历史查询结果，状态已变化”；不得自动重发检索，因为每次新搜索都会增加命中数。也不能将旧候选集重新排序伪装成新搜索。

### 3.3 任务追踪

输入taskId查询，或从本会话提交记录进入 → 显示真实状态/时间/错误 → 在排队或运行时可自动刷新 → 终态停止。页面刷新后仅可恢复会话保存的taskId，再向服务端取真实状态。

本版不要求全局任务列表API。任务Tab由“按ID查询”和“本会话任务”组成，不能把本会话列表称为全系统任务。

## 4. 页面规格

### 4.1 Tab A：检索体验

| 元素 | 规格 | 说明 |
|---|---|---|
| 查询文本 | 多行输入，允许空字符串 | 空查询时显示“将返回零分排序结果，不能区分相关性” |
| Top-K | 数字输入，默认5，范围1—100 | 禁止小数、负数、0；服务端仍需校验 |
| 渠道 | 可选文本，默认全部渠道 | 空输入通过省略字段表达，不能发送空字符串 |
| 检索按钮 | 点击后loading，当前请求完成前防重复提交 | 不使用输入即搜索，不做自动刷新 |
| 耗时 | 浏览器实际测量的请求往返耗时 | 标签写“请求往返耗时”，不是“纯后端计算耗时” |
| 结果数量 | 实际hits.length | 不冒充全库候选数或召回率 |
| 结果卡片/表格 | 排名、ID、score、channel、摘要、详情按钮 | score显示4位小数，排序保持后端顺序 |

**score规范：**显示真实余弦分数，允许负数；不显示“匹配率95%”“AI置信度”等含义不同的指标。小数显示相同也不在前端重新排序，后端基于完整分数及ID决定顺序。

结果状态：首次未搜索、检索中、成功有结果、成功无结果、400参数错误、401/403访问受限、429/503繁忙、网络失败。网络失败提示“无法确认本次请求是否已完成；再次检索将视为新请求”，不自动重试。

更改筛选条件后保留上一次结果但标注“以下为上次查询条件的结果”，或清空并提示尚未执行新查询；不得把旧结果当新条件结果。

### 4.2 Tab B：文档管理

上方提交表单，下方分页列表。

| 提交字段 | 规则 |
|---|---|
| documentId | 非空、长度上限与后端契约一致；不擅自把ID改成数字 |
| text | null不允许；输入框空值发送空字符串，允许空文档 |
| channel | 可选；空白UI输入表示未填写，省略字段，由服务端设default |

前端不裁剪原文、不替用户做NFKC/小写、不拼接向量；规范化由后端统一处理。只对ID/渠道按契约处理空白。

提交成功提示：`已接收文档 <ID>，任务 <taskId>。向量化在后台执行，完成前不可检索。`

| 列表列 | 显示与交互 |
|---|---|
| 文档ID | 点击详情，长ID截断但可复制完整值 |
| 渠道 | 原值展示 |
| 任务状态 | 排队中/处理中/完成/失败 |
| 向量就绪 | 是/否，不能用分数或范数猜测 |
| 有效状态 | 有效/已失效，独立于任务状态 |
| 提交/完成时间 | 北京时间；未完成显示“—” |
| 命中次数 | 后端返回值，单次页面读取的快照 |
| 操作 | 详情、失效；已失效时禁用重复操作并可查看状态 |

筛选只要求渠道、有效状态；默认page=0、size=20，上限100。翻页不丢筛选。列表数据不包含向量数组。没有自动刷新统计的需求，提供“刷新列表”按钮即可。

ID重复409明确提示“不覆盖已有文档，请查询详情或使用新ID”；不能遇到409自动换ID再次提交，否则掩盖用户意图。429提示服务接收容量已满，不把文档假加入成功列表。

### 4.3 文档详情抽屉

显示ID、渠道、原文、taskId与taskStatus、vectorReady、invalidated、提交/开始/完成/失效时间（字段存在时）、hitCount、失败原因（有则显示）。算法版本可由后端提供后展示，不强制扩展API。

原文纯文本展示、可复制、可滚动；不直接渲染HTML，不把原文中的链接自动执行。查询详情本身不增加命中数。

**失效确认：**“失效后该文档不会参与新的检索，本演示不提供恢复有效操作。是否继续？”

按钮提交后等待后端成功才更改有效状态。与向量任务并发时，页面允许同时显示“任务完成 / 文档已失效”。请求失败保留原状态并显示错误，不乐观伪报成功。

### 4.4 Tab C：任务追踪

| 内容 | 行为 |
|---|---|
| taskId输入 | 支持粘贴查询，不存在404有明确提示 |
| 当前任务状态 | 四态文字，不伪造百分比 |
| 关联文档 | 成功/失败均可展示已有documentId；详情仍由API获取 |
| 时间 | 已提供的提交、开始、结束时间；缺失显示— |
| 错误 | 展示安全的errorCode/message，不显示SQL与堆栈 |
| 本会话任务 | 最多保留20个ID，明确不是全局列表 |

不能因为一次GET网络失败就把任务状态设成FAILED。正确显示为“状态暂不可获取；上次已知状态：RUNNING”。FAILED只能来自后端业务状态。

## 5. API契约建议

本节是开发冻结模板，不是已存在接口的抓包结果。主控需要与后端一起确认后再交给前端；任何变更同步所有Agent。

### 5.1 通用JSON对象

```text
TaskView:
  taskId, documentId,
  status: QUEUED | RUNNING | SUCCEEDED | FAILED,
  submittedAt, startedAt?, finishedAt?,
  errorCode?, errorMessage?

DocumentSummary:
  documentId, channel,
  taskId, taskStatus,
  vectorReady, invalidated,
  submittedAt, vectorCompletedAt?, invalidatedAt?,
  hitCount

DocumentDetail:
  DocumentSummary + text

DocumentPage:
  items: DocumentSummary[], page, size, totalElements

SearchResponse:
  hits: [{ documentId, channel, score, snippet }]

ErrorResponse:
  code, message, fieldErrors?, requestId?
```

`snippet`由后端生成，原文详情独立获取；前端不要求增加全量向量、全库统计和LLM解释字段。`requestId`若未实现就不显示假值。代码、schema字段名和JSON字段名应明确映射。

### 5.2 接口映射

| 操作 | 接口 |
|---|---|
| 文档提交 | POST /api/documents |
| 分页列表 | GET /api/documents?page=0&size=20&channel=...&invalidated=... |
| 详情 | GET /api/documents/{documentId} |
| 失效 | PUT /api/documents/{documentId}/invalidation |
| 任务 | GET /api/tasks/{taskId} |
| 检索 | POST /api/search |

路径参数必须URL编码。具体ID允许字符在后端契约中固定，不能让前端自己假设任意斜杠都可放入路径。

默认渠道规则必须分开：提交不传→default；搜索不传→全部。表单留空时省略可选字段，不发送显式空白channel。

## 6. 轮询、请求竞争与取消

**建议起点：**排队/运行任务每2秒刷新，单任务最多自动刷新60秒；到时提示“自动刷新已暂停，任务可能仍在后台运行”，提供手动刷新。终态立即停止。最多3个任务同时自动轮询，其余手动查询。

采用完成一次再安排下一次的方式，避免setInterval造成请求重叠；页面隐藏时暂停，返回可见后再查询。5xx/网络失败采用有限退避并显示状态，不无限高频重试。

检索请求用loading防重入，或用序号忽略旧响应，不能让先发后到的旧结果覆盖新结果。AbortController只停止浏览器等待/读取，不能证明服务端已停止执行或命中事务已回滚。[S2]

搜索和提交不进行自动重试：网络超时不代表服务器未接收。提交结果未知可按已知documentId查询详情；检索再次执行会再次计数。GET列表/任务可以有限重试，因为其本身不修改命中数。

轮询时间和并发是产品默认值，不是实测性能最优参数。

## 7. 视觉与交互说明

采用紧凑、清晰的后台工具风格：浅色背景、中性边框、单一强调色；状态除颜色外必须有中文文字。正文不小于14px，主内容约1200px宽度，桌面优先，窄屏表单垂直排列、表格可横向滚动。

主操作“检索”“提交文档”清晰区分；失效属于危险操作，必须有确认。输入项有label，键盘可操作，焦点可见；错误显示在字段附近并保留输入。长文本不挤压任务/状态区域，详情使用独立滚动区。

无需动效、插画、头像、聊天机器人形象或复杂设计系统。此文档提供产品规则，不输出已定稿视觉稿或已实现截图。

## 8. 安全与诚实展示

- 所有来自后端/用户的文本通过textContent或等价转义方式展示，防止脚本注入；不使用未经处理的innerHTML。[S3]
- 访问凭据不写入JS、本地存储、公开README；正式入口认证交给部署层。
- localStorage/sessionStorage仅可保留少量任务ID/非敏感偏好，默认不持久保存完整文档原文。
- 不自动填充假搜索结果；开发mock需要明确“开发模拟数据”标识，正式构建不启用。
- 不展示从未测量的QPS、准确率、CPU曲线、后台耗时和完成百分比。
- 浏览器时间是展示层；业务状态与时间以服务器为准，时区标注UTC+8。
- 文档被搜索命中不代表用户阅读；页面不会把详情打开动作再记为一次检索命中。

## 10. 工作量与裁剪

建议1.5—2.5小时有效实现量，前提是API先冻结且开发者能调试JS；这不是时间保证。优先完成提交、真实任务查询、搜索结果、列表详情和失效；其次补网络错误与轮询停止。

时间不足可将Tab改为单页上下分区、取消抽屉改内联详情、取消复制按钮与自动恢复任务列表；不能删除真实接口接入、错误提示、失效确认和任务四态，也不能用mock冒充完成。
