# 多Agent任务拆分与Codex实施指令

> 日期：2026-10-22；版本V1.1。  
> 这是协作计划与可复制指令，不代表本次已经启动Agent、修改GitHub仓库或执行服务器命令。

## 1. 是否有必要

可以轻量并行，建议最多2—3个写入任务同时进行，不必让后端、服务器、前端和测试四个角色全程并发。**角色划分有用，但共享文件冲突、接口变更、代码审查和联调可能抵消收益。**

对这个项目，最合适的结构是“主控统一契约 + 一个后端Owner + 前端和部署短任务并行 + 独立测试审查”。不建议把任务领取、事务、队列、状态回写进一步分给四个不同Agent。

Codex官方资料提供子Agent与worktree能力，适用于边界明确的任务。实际是否可用、入口在哪里，以当前安装版本和账户功能为准。没有自动子Agent入口时，用独立会话+Git worktree也可执行本方案。[S1、S2]

## 2. 唯一最高优先级与范围变更

每个Agent先读原题PDF及仓库AGENTS.md，再读本资料包主报告和API契约。

- 原题优先于研究建议：Java17+、Spring、MyBatis/JPA、H2嵌入式文件、Java队列、固定256float、同文确定、空文零向量、异步入库、同步检索。
- 本轮用户新增：需要服务器部署；需要简单前端；准备使用GitHub。
- 因此旧文档中“不做前端”和“部署首先削减”的条款失效；只允许裁剪页面装饰、复杂自动化与额外优化。
- 不增加MySQL、Redis、MQ、真实Embedding、LLM、向量数据库、分布式调度、文档解析与聊天页面。
- 未运行的测试写“未执行”，不允许推测通过；不虚构性能、准确率和截图。

## 3. 工作包与所有权

| 角色 | 可修改范围 | 交付 | 禁止事项 |
|---|---|---|---|
| 主控/集成 | 根配置、契约、DDL、公共DTO、最终README与合并 | 统一可构建基线和决策 | 不把合并冲突全自动交给Agent |
| 后端 | Java业务包、Mapper及自己的单元测试 | 向量/任务/检索/管理正确性 | 未批准不改契约、DDL、依赖代际 |
| 前端 | src/main/resources/static/**，独立页面测试 | PRD三功能区与真API联调 | 不改Java、SQL、pom，不伪造数据 |
| 部署 | deploy/**、部署脚本、CI配置提案 | 单实例运行和回滚说明 | 不获取/提交长期云主密钥，不擅自发布 |
| 测试 | 独立acceptance测试目录、测试说明 | 失败用例、真实验证结果 | 不删断言、不改业务使测试变绿 |

测试代码目录按功能隔离，例如后端单测在`.../unit/`，测试Agent在`.../acceptance/`。测试依赖和Failsafe配置由主控统一调整，避免两名Agent抢改pom.xml。

## 4. 并行前先冻结的契约

至少用45分钟完成以下基线，否则前端和测试会各自猜测：

1. 六个API的方法、路径、请求/响应字段及统一错误格式。
2. status四态、vectorReady、invalidated的独立含义。
3. 提交缺省渠道default，检索缺省全渠道；前端空输入省略channel字段。
4. null文本400、空字符串合法、重复文档409、失效幂等。
5. 分数降序/同分ID升序，零范数分数0，无阈值；空查询允许且提示。
6. 同实例H2、独立测试数据库、任务恢复与命中统计语义。
7. 最小接口类型/公共DTO与数据库schema。
8. 测试、启动和打包命令，项目目标JDK。

公共契约文件建议为`docs/api/api-contract.md`或一份手写OpenAPI，择一作为事实来源，不能多份同时漂移。OpenAPI不是额外Swagger服务的硬要求。

## 5. 分支/worktree安排

先由主控提交可构建骨架；每个Agent从同一个契约基线派生分支。

示意命令（只作为操作示例，实际执行前确认仓库与分支状态）：

```bash
# 在已存在且有初始提交的Git仓库中执行。
git worktree add ../vector-backend -b feat/backend-core main
git worktree add ../vector-ui -b feat/demo-ui main
git worktree add ../vector-deploy -b chore/deployment main
# 验收测试分支可在核心接口合入后再创建，减少过早分叉。
```

Git worktree提供独立工作目录与分支；它不隔离端口、数据库、环境变量或CPU。[S3]

建议开发约定：主控8080、后端8081、前端联调8083；每个应用使用独立绝对或工作区相对H2目录。具体端口只用于本地，不直接开放公网。CI使用临时目录与随机可用端口。

不要让多个Agent在同一个工作目录执行checkout/reset、自动格式化全仓、重写提交历史、清理其他Agent文件。

## 6. 依赖图与推荐波次

```text
主控：契约/骨架/DDL
        ├─ 后端核心 ─────────┐
        ├─ 前端页面（契约） ──┤→ 主控合并 → 真API联调 → 故障回归 → 发布
        └─ 部署骨架/环境 ────┤
测试：先写验收设计，再接真实实现 ┘
```

**波次一：**主控冻结基线，部署角色检查服务器条件。

**波次二：**后端实现核心；前端做页面并按契约开发；部署准备systemd/代理和早期试跑。测试角色只读审查/编写用例，不同时争改业务代码。

**波次三：**后端接口合入后，前端真联调，测试执行竞态与恢复；部署脚本根据真实配置收敛。

**波次四：**主控停止并行新增功能，统一回归，生成同一SHA的发布包，服务器验收后交付。

加Agent数量不会自动缩短主控的审查时间。第一次使用worktree或多Agent时，优先“后端+前端”两个写入任务，部署与测试按短任务切换。

## 7. 可复制：主控总指令

```text
你是本项目集成负责人。先阅读原始笔试PDF、AGENTS.md、01_业务分析与工程实施方案、03_简版前端产品设计文档和仓库现状。

原题优先；用户新增要求是服务器部署和简版页面。不要沿用旧指令中的“禁止前端/部署可直接删除”。

先完成C0：确认Java/Maven一致、依赖代际匹配、H2文件库可启动，冻结六个API、错误格式、DDL和公共DTO。不要生成整套超范围系统。

之后仅给边界明确的工作使用独立分支/worktree：核心后端一个Owner，前端仅static，部署仅deploy/脚本，测试独立acceptance目录。pom.xml、schema.sql、公共契约由你统一管理。

每个阶段输出：实际修改文件、commit、真实运行命令与结果、未执行项、已知风险、下一步依赖。所有功能和测试必须以真实运行证据报告。禁止虚构性能或补造Git时间线。

你必须人工审查：实际事务提交点、条件更新行数、字段覆盖、队列拒绝、run_token、命中统计重试、资源上限、H2路径与恢复、UI网络错误和轮询停止。

只有集成测试与本次最小交付验收通过，才生成带SHA的发布包；服务器使用单实例H2文件，不使用MySQL。任何影响生产数据、凭据、权限或清理操作先提出方案，不擅自执行。
```

## 8. 可复制：后端工程Agent

```text
你负责Java后端核心，只修改分配的业务代码、Mapper和单元测试；公共契约/DDL/依赖变更先提出，不独自改动。

实现：确定性256维向量器、codec、余弦、小顶堆；文档和QUEUED任务同事务；持久扫描+有界ThreadPoolExecutor；条件领取与run_token；事务外计算；向量和成功终态同一短事务；任务查询；文档列表/详情/幂等失效；同步搜索；最终Top-K原子计数。

必须覆盖：空文本与null区别、同文按位一致、同分ID排序、过滤先于Top-K、提交后未入队故障、重复领取、完成与失效并发、容量上限、计数并发、提交结果未知不盲重试、重启恢复。

不得整体保存旧实体覆盖invalidated/hit_count；不得CPU计算长时间占数据库事务；不得用CallerRuns或丢弃策略隐藏过载；不得以sleep冒充CPU计算；不得查询端偷偷换算法。

阶段验收后给出真实命令和结果。不能运行时明确说明，不写“应该通过”。不自行增加手工重试、更新原文或多实例逻辑。
```

## 9. 可复制：前端工程Agent

```text
你只负责src/main/resources/static内的简版演示台。阅读PRD与冻结API契约，不修改Java、DDL或pom。

用原生HTML/CSS/JS实现检索体验、文档管理、任务追踪三个功能区及详情。所有数据通过真API获取，开发mock必须显式标记且不得进入正式运行。

提交成功只表示接收，显示真实taskId；任务轮询每2秒、终态停止、最长自动刷新60秒、页面隐藏暂停，最大3个任务同时轮询。网络失败不能将任务标成FAILED。

空文档允许；查询渠道空白省略字段表示全部；提交渠道省略表示default；分数是余弦不是概率；负分和同分按后端顺序显示。搜索不自动重试，因为每次可能增加命中数；失效后不自动重搜。

用户原文使用安全文本展示，不用innerHTML，不在JS存凭据。实现loading、空状态、参数错误、繁忙、网络失败与失效确认。

交付时列出真API联调结果和浏览器验证情况；没有实际浏览器工具或未执行时，写“未完成浏览器验证”，不能编造截图。
```

## 10. 可复制：服务器/部署Agent

```text
你负责部署设计与脚本，不修改业务规则。目标是单台Linux、单JVM、H2嵌入式文件、JAR+systemd+Nginx。

先核对实际服务器JDK、账号、路径、端口、磁盘和访问条件。应用仅监听127.0.0.1:8080；数据库独立持久目录，release切换不改变H2路径；不装MySQL、Redis或H2独立服务。

产出非root运行、开机启动、失败重启、日志保留、HTTPS/入口认证、请求体及速率限制、发布、正常停止、备份与回滚说明。认证覆盖页面和API，H2 Console和管理端点不对公网开放。

部署包标记Git SHA和校验和。先试跑骨架，再发布集成版；不能同时启动两个版本挂同一H2。普通数据库文件复制必须先正常关闭，恢复测试在独立路径执行。

未经明确授权不登录/改生产、不调整防火墙、不删除数据、不获取长期主密钥。示例凭据只用占位符；真实凭据由用户通过安全渠道设置，绝不进入Git或AI对话记录。

输出真实命令结果、未验证步骤和回滚条件；不把配置文件生成当作已部署成功。
```

## 11. 可复制：测试/审查Agent

```text
你是独立测试与代码审查角色，优先发现缺陷，不替实现辩护。先读原题和契约，再核对实现。

用latch/barrier等明确控制竞态，不用随机sleep当证明。重点测试：异步返回、未完成排除、重复领取、提交后不派发、向量与终态事务回滚、完成/失效交错、并发命中、容量竞态、文件库重启、子进程强杀恢复、未知提交结果。

前端重点：真实状态、空输入、查询/提交channel区别、轮询停止、网络失败不误判FAILED、检索不自动重试、原文不执行脚本。

部署重点：独立持久目录、非root、单实例、未认证API不可访问、管理端口不暴露、SSH断开服务存活、版本SHA与构建一致。

不允许删除失败断言或把期望值改成当前错误行为。发现实现问题，以复现步骤、预期、实际和最小证据报告，由Owner修复。输出通过/失败/未执行分表，不填虚构覆盖率或压测结果。
```

## 12. 每个Agent统一的交付格式

```text
任务/分支/基线SHA：

运行命令：
真实结果：
未执行/未验证项：
已知风险与复现方式：
建议主控审查的关键位置：
提交commit：
```

禁止只提交“完成了、没有问题”式总结。

## 13. 合并门禁

- [ ] 先看契约差异，再看业务代码，最后看测试，不只看CI绿色。
- [ ] 相同事务或Mapper不能由多个Agent分别做互不知情的修补。
- [ ] 每次合并后重新运行集成测试；分支各自通过不代表合并后通过。
- [ ] 代码、DDL、前端字段、README和部署配置保持同一版本。
- [ ] 保留真实迭代记录，不伪造提交时间。
- [ ] 最后发布阶段只有主控操作版本切换，其他Agent停止改共享主线。
- [ ] 最终交付中列出仍未验证的容量/性能/故障边界。
